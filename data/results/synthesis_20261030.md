# Skill 生态数据规律总览（2026-10-30）

> 通读本项目全部历史分析（10-12 至 10-30，十余轮挖掘、80 余项检验）后的整体性总结。
> 目的不是复述论文五命题，而是回答：**这批数据本身服从什么规律**。
> 每条规律标注数字、口径、覆盖度与出处；不能当因果读的地方明确标注。

## 一、十条规律

### 规律 1：重尾是默认状态，三组核心量的尾指数 ≈ 2

Clauset–Shalizi–Newman MLE + KS 选 x_min，五组量全部优于对数正态与指数：

| 量 | α | x_min | 尾部 n | KS |
|---|---|---|---|---|
| 父仓 PR 事件 | **1.99** | 1,226 | 60 | 0.056 |
| 回流 PR/作者 | **2.03** | 39 | 1,184 | 0.033 |
| 合并时滞（小时） | **2.21** | 223 | 1,500 | 0.069 |
| 父仓回流 fork | 2.41 | 647 | 47 | 0.084 |
| 评论线程长度 | 3.19 | 9 | 888 | 0.128 |
| 评论字符数 | 3.39 | 13,644 | 1,457 | 0.025 |

**含义**：α≤2.1 的三组量理论方差发散——"平均仓库""平均作者""平均合并时间"在统计上不存在，
必须用中位数/分位数/对数尺度。任何用均值±标准差的表述都会被少数极端仓主导。
配套集中度：回流作者 Gini **0.719**（单人最多 6,594 个 PR）；skills.sh 安装 Gini **0.946**
（top1 占 39.5%）。

### 规律 2：扩散是短爆发 + 慢衰减，不是持续涓流

- **爆发检测**（Kleinberg 两状态泊松 + Viterbi）：340 仓中 337 仓可判，仅 1 仓无爆发段；
  每仓爆发段中位 **3 次**（p90=14）；**74.3% 的爆发 ≤2 周**；爆发周占生命史中位 13.2%；
  强度极值达基线 **1,800×**。
- **爆发主导**：80.6% 的仓只有一个非零 attention shift；条件于 66 个多段仓，
  top1 shift 仍吃掉 **99.8%** 的星标。
- **衰减极慢**（Omori 式）：p = **0.235**（R²=0.986，12,586 个爆日），
  对比视频/新闻平台的 0.7–1.0——这里的注意力事件是"持续曝光段"而非脉冲。
- **周增量有强动量**：ΔL 自回归系数 **+0.626**（p=1.5e-41），Hall 随机游走被明确拒绝
  （R²=0.476）。规模系数 +0.00196（p=8e-9），弱优先连接。
- **宏观节律**：日事件序列 lag1–14 自相关 0.92–0.98，Fano 因子 615（泊松=1）；
  周末事件降约 30%；小时分布峰在 9 时 UTC。

**含义**：周均值类指标失真；"热度"应表述为"爆发时间占比 + 衰减曲线"，不能表述为平均水平。

### 规律 3：增长亚线性，头部靠减速领先

池化 34,888 个周对、对数分箱拟合 log ΔS ~ log S：**PA 指数 0.61**（SE 0.044，R²=0.951）。
经典 BA 模型的线性优先连接（指数=1）被拒绝——规模每翻一倍，增量只增约 1.5 倍。
**含义**：这个生态没有"赢家通吃式加速"，头部优势来自早期领先后的减速维持，而非累积加速。

### 规律 4：漏斗层层收窄，且层与层之间几乎不互相预测

341 仓五级漏斗：有星 341 → skills.sh 命中 146（42.8%）→ ClawHub 命中 78（22.9%）
→ 有 PR 196 → 有回流 PR 224/225（99.6%）。
渠道间两两相关极低（skills.sh×ClawHub .163、×release .047、ClawHub×npm .094），
仅 23.8% 的仓只在 GitHub 单渠道可见，平均 2.36 个渠道。

**平台命中不预测贡献**：命中仓回流转化中位 4.66% vs 未命中 3.01%（p=0.25）。
**注意力不预测采纳转化**：conversion ~ log 星标 + log fork + 年龄，R²=**0.007**，
星标 Spearman ρ=0.06（p=0.37）。

### 规律 5：采纳→贡献弱耦合、双峰、且与注意力无关

- **总量**：fork→PR 转化率 **6.67%**（225 父仓，122,235/1,832,187，Wilson 95% [6.64%, 6.71%]）；
  每仓中位 **3.95%**（q25 1.76%、q75 7.56%）。按 links 去重独立复算为 6.41%，
  差 0.26pp 来自匹配方式（head_repo vs 全方式），不影响结论。
- **双峰**：12 个父仓（5.4%）贡献一半回流 fork；流水线仓转化 46% vs 长尾仓 5%。
  极端例：punkpeye 55.9%、ultraworkers 0.06%。
- **时间断崖**：回流时距 <1h 占 **27.9%**、1–24h 9.1%、7 天以上 **52.0%**——
  "立即同步"与"永不回流"两个世界，中间地带很薄。
- **作者集中**：99,797 名作者 Gini 0.719；父仓内 top1 作者份额中位 10.9%。
- **事件量**：每回流 fork 平均 3.66 个 PR；2026-03 起月均 3–5 万，2026-09 峰值 52,819。

**含义**：P2 的不是"转化率低"，而是"**结构化分层**"——少数同步流水线仓 + 多数近零转化仓；
"贡献"在这批数据里更像自动同步，而非贡献承诺。

### 规律 6：把关稀薄、单点、留言式，且合并结果几乎不可预测

- **过半无痕迹**：严格口径下 **53.2%** 的合并既无正式审查也无评论；已合并 PR 中
  "两者皆无" 46.4%，仅评论 15.2%、仅审查 15.6%、双轨 22.8%。
- **双轨同量级**：合并前评论覆盖 38.0% ≈ 正式审查 38.4%；仅评论无审查 28.6%（全量 PR）
  / 15.2%（已合并 PR）。
- **留言式审查**：COMMENTED 26,446 vs APPROVED 5,741 vs CHANGES_REQUESTED 2,065
  ——"留言"是"正式决定"的 **4.6 倍**；review 正文空 32.8%；changes→merged 仅 0.7%。
- **单点把关**：有 ≥10 条评论的 120 仓中，top1 评论者份额中位 **57.9%**（p90 84.2%）；
  **64.8%** 的仓由单一账号执行九成以上合并。
- **不可预测**：静态特征 AUC **0.531**（五折 0.483–0.575，接近随机）；
  加入 24h 内评论/审查后 AUC 0.590。重要度最高的是 PR 编号（0.212，时代代理）。
- **审查是通道不是闸门**：仓级回归（n=61）审查覆盖 +0.64（p=.012）、
  把关集中度 +0.385（p=.027）、合并率 R²=.257（截面相关）。

### 规律 7：合并有两条时间车道，机器人是捷径

| 分组 | KM 中位合并时滞 | 检验 |
|---|---|---|
| 无评论 | **5.4 h**（n=20,458） | — |
| 有评论 | **367 h** | logrank χ²=2,701 |
| 无正式审查 | 70.4 h | — |
| 有正式审查 | **52.0 h** | χ²=158 |
| 人类作者 | 66.1 h | — |
| 机器人作者 | **20.9 h** | χ²=41 |

仓内 PR 编号近邻 1:1 配对（3,668 对/96 仓）：Δlog 时滞中位 1.621，bootstrap CI [1.47, 1.74]
→ **5.06×**［4.35×, 5.71×］。
合并 PR 的中位时滞 7.7h，而关闭未合并 98.9h——**拒绝得快、接受得也快，拖延只发生在关闭侧**。

**读法**：评论标记的是争议/复杂 PR，审查标记的是走流程的常规 PR；方向是"伴生"不是"导致"。

### 规律 8：溯源在生产端就稀薄，复制过程不磨损署名

- **署名时间戳**（544 侧可判）：**71.3% 从未写入**、26.8% 诞生即写、仅 **1.8% 后补**。
- **方向性**：父侧署名早于子侧文件出现 **68/70 = 97.1%**（Wilson [90.2%, 99.2%]）；
  署名时序与文件首创方向一致 68/68，其中非平凡一致 8/8。
- **复制不磨损**：有署名复制对沿方向保留 97.1%（精确复制对口径）；
  近重复 4,000 对的条件保留率为 77.8%（含修改对），两个口径不可混用。
- **文档短命**：每文件提交数中位 **1**（p90 5）；复制后子侧再编辑仅 **13.6%**；
  署名与否不影响维护强度（p=0.31）。
- **署名与注意力无关**：署名率 vs 星标 ρ=−0.10（p=0.45）。

**含义**：P3 的机制不是"复制时把署名抹掉"，而是"**生产端根本不写**"；
"复用—溯源不对称"发生在创作瞬间，不在流转过程。

### 规律 9：五个"流行度"指标不可互替，覆盖度会翻转符号

| 指标对 | 秩相关 | 口径 |
|---|---|---|
| 星标 × fork | **0.94** | 341 仓（同构念两种测量） |
| 星标 × skills.sh 安装 | **−0.04** | 341 仓，缺失置零（覆盖 42.8%） |
| 星标 × skills.sh 安装 | **+0.20**（p=.007） | 172 仓，仅有安装观测（**符号翻转**） |
| 安装 × ClawHub | 0.295 | 共同非零 |
| 星标 × ClawHub | 0.287 | — |
| release 下载 × 其余 | 均 <0.3 | — |

**含义**：Deaton 式批评成立——五个指标测五种不同的东西；
"缺失置零"会造出虚假负相关，任何跨渠道结论必须报覆盖度子样本口径。
几何合成（HDI 式）与纯星标排名 ρ=**0.868**，说明排序有实质重排空间（垂类/策展仓被低估）。

### 规律 10：结构分型稳定——六型仓库、灌木网络、操作手册话语

- **仓库六型**（KMeans k=6，轮廓 0.309，225 仓）：长尾 77（转化 5%）、平台可见 42、
  明星 76、**流水线 7（转化 46%）**、**镜像注册表 13（跨仓复制 0.92、技能比 0.96）**、
  分发 10（合并率 0.60）。
- **复制网络**：Louvain 模块度 **0.39**、197 社区、最大 452 仓——"大块+碎块"，
  三大社区对应三大搬运生态。
- **评论者网络是灌木**：4,538 人中 **93.9% 只出现在一个仓**，度中位 1、最大 28；
  二部图 NODF **15.1**（低嵌套 = 专业化，不是"大仓名单顺带出现"）。
- **文本是操作手册**：LDA 12 主题中执行/计划/API/测试占绝对多数，
  "关于技能本身"的元话语单独成簇 10%。评论六簇：行政收尾 34.7%、通用审查 30.6%、
  **AI 评审摘要 17.4%**、安全审计 10.8%、打包 3.4%、CLA 3.1%。

## 二、统一解释：四层解耦的"弱耦合"

十条规律可以压成一句话：**这个生态在四个环节上各自独立地"少数通吃、多数为零"，且环节之间互不预测。**

```
注意力（星标）──弱──> 采纳（fork/安装）──弱──> 贡献（回流 PR）──弱──> 溯源（署名）
   重尾+爆发            渠道不可互替          6.67%/中位3.95%          71.3% 从不署名
   PA 0.61              平台命中不预测         与星标 R²=.007          复制不磨损
```

- 层内：每层都是"少数高转化通道 + 多数近零"的双峰结构（12 仓一半回流、7 仓 46% 转化、
  64.8% 仓单账号把关、93.9% 评论者单仓）。
- 层间：注意力不预测采纳（R²=.007）、采纳不预测贡献强度（ρ=.06）、贡献不带来溯源（ρ=−.10）。
- 时间上：所有过程都是"瞬时或永不"——回流 <1h 27.9% / >7d 52%，合并 7.7h vs 关闭 98.9h，
  文档一次写成（中位 1 次提交）。

因此"扩散"在这批数据里更像**分发**（distribution）而不是**共同体**（community）：
内容被搬运、被安装、被同步，但很少被讨论、审查、署名或共同维护。

## 三、反直觉清单（每条都可复算）

1. **星标完全不预测贡献转化**：R²=0.007，ρ=0.06（p=0.37）。
2. **审查越多，合并率越高**（+0.64，p=.012）——审查是通道不是闸门。
3. **有评论的 PR 合并慢 5 倍**（367h vs 5.4h），但只有 38% 的合并有评论。
4. **合并结果几乎不可预测**：AUC 0.531（静态）/ 0.590（+24h 信号）。
5. **署名缺失不是复制造成的**：71.3% 的文件从来没写过署名，复制对保留率 97.1%。
6. **平台收录不预测回流**：4.66% vs 3.01%（p=0.25）。
7. **"平均热度"没有统计意义**：α≈2，方差发散。
8. **增长不是赢家通吃**：PA 指数 0.61（亚线性），不是 BA 的 1。
9. **随机游走被拒绝**：周增量自回归 0.626，星标增长是强动量过程。
10. **安装量与星标几乎无关**（置零口径 −0.04；有观测子样本仅 +0.20），
    与"安装是更真实的使用度量"的直觉相反。

## 四、方法学：这批数据接受什么、拒绝什么

**适用**：幂律 MLE+KS（重尾）、爆发度/Fano/两状态泊松（点过程）、
KM/logrank/Cox（删失时间）、GroupKFold（防仓内泄漏）、
KMeans/GMM+轮廓、IsolationForest、Louvain、NODF、LDA/TF-IDF、
仓内近邻配对+bootstrap、强约束检验（Hall 式 β=0）、部分识别/重排界、Granger/VAR。

**数据会拒绝的**：泊松假设（Fano 615）、均值±标准差（α≤2.1）、
把转化率当连续正态做 t 检验（双峰重尾）、把"有评论→慢"读成因果（选择效应）、
把置零后的跨渠道相关当真实关系（符号会翻转）。

**六个口径陷阱（本轮全部踩过并修正）**：
1. `n_matched` 是 PR 条数不是 unique 贡献 fork 数（6.67% vs 6.41%）；
2. skills.sh 明细在 `market_full.jsonl`（296 条）而非 `skills_sh_prefix.jsonl`（3 条汇总）；
3. 方差分解不能用朴素分量相加（不正交，和=104.6%），要用嵌套 R²；
4. 特征筛选不能掺入留出折（选择泄漏，test R² 虚高 0.15）；
5. 占比类指标要检查分母是否退化为 1（80.6% 仓单 shift 使 99.8% 近乎机械）；
6. 缺失置零会翻转相关符号（星标×安装 −0.04 vs +0.20）。

## 五、未解问题与可升级的识别策略

| 问题 | 现状 | 升级路径 |
|---|---|---|
| 因果识别（注意力→贡献） | 只有 Granger/事件级时序（星标→fork 97.4% 显著） | 平台收录阈值 → RDD；首页推荐随机排序 → 抽签式 IV |
| 事件冲击效应 | 3 次安全披露事件，无对照 | 合成控制（Abadie）+ 供体池 + 安慰剂检验 |
| 复杂传染/阈值 | 342 对复制对，簇规模太薄 | 补全 19k 复制簇的 SKILL.md 历史（3–5 天采集） |
| 样本代表性 | skills.sh 安装者是有偏早期样本 | MRP 事后分层（需开发者总体的分层边际） |
| 跨期趋势 | 星标窗口中位 41 周，长短不一 | 接 GitHub Archive 全历史 + 左截断校正 |
| 把关准则 | AUC≈0.53，元数据无信息 | 需 PR diff 内容/文件路径级特征（未采集） |

**一句话**：这批数据里的"扩散"是**分发驱动的弱耦合**——注意力、采纳、贡献、溯源四层各自重尾、
各自双峰、彼此几乎不预测；少数流水线/镜像/分发仓承担了绝大部分流量，
而绝大多数仓库、PR、文档只在"瞬时或永不"两端出现。
